# Wiki Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed-in `/wiki` page with detailed instructions, linked from every screen's menu.

**Architecture:** One module renders the page with the existing `_layout` and `_tabs` helpers; the text is Python data in that
module. `tabs.js` does the switching, so there is no new script or asset.

**Tech Stack:** Python 3.12, FastAPI, server-rendered HTML, pytest.

**Spec:** `docs/superpowers/specs/2026-11-27-wiki-page-design.md`

## Global Constraints

- New branch `feat/wiki` from local `main` (`f699a22` or later). Do not push.
- Roles: `ADMIN`, `WAREHOUSE_AUTHORITY`, `SECURITY`. Anonymous is redirected to `/`.
- All text through `esc()`; same security headers; no inline script or style; no names, phones, keys or addresses.
- Quote button, tab and message wording exactly as the screens have it. Read the code before writing each instruction; leave out
  what cannot be confirmed.
- English only. Tests: `.venv\Scripts\python.exe -m pytest <files> -q`; finish with `py -3.12 scripts/ci.py`.

## Review Focus

1. An instruction names a button or tab that does not exist (Task 1 test).
2. A security user opens the page and sees links to screens they cannot open (Task 1 test).

### Task 1: The page and the menu link

**Files:**
- Create: `src/setuhaul/auth/wiki_pages.py`, `tests/test_wiki.py`
- Modify: `src/setuhaul/auth/pages.py` (route in `register_pages`; `nav` in `render_admin` and `render_warehouse`),
  `src/setuhaul/auth/gate_pages.py` (`nav`), `src/setuhaul/auth/assets/app.css` (only if lists need spacing),
  `tests/test_auth_role_matrix.py`, `docs/running-and-demonstrating.md` (one line in section 7a)

**Interfaces (produces):**
- `wiki_pages.render_wiki(user: User) -> HTMLResponse`
- `wiki_pages.TOPICS: tuple[tuple[str, str, tuple[tuple[str, tuple[str, ...]], ...]], ...]` as
  `(tab key, tab label, ((task heading, (step, ...)), ...))`
- Route `GET /wiki`

Menu: each screen keeps its links and gains `<a href="/wiki">Wiki</a>` last. The wiki's own menu shows only screens the role
can open: admin gets Warehouse, Admin, Gate; warehouse gets Warehouse; security gets Gate; all get Wiki.

Content (tab key, label, tasks to cover):

| Key | Label | Tasks |
|---|---|---|
| `start` | Getting started | Sign in (Google, backup password); roles and what each can open; the usual day from shipment to gate |
| `warehouse` | Warehouse | Attention strip; dock board colours; free a slot; block and reopen a dock; cases (claim, resolve, reopen); facility requests; chats; projects; open availability and create a shipment; change driver, cancel, pass actions; add a driver, Telegram revoke and re-link; delete a driver |
| `admin` | Admin | Invite and disable users; approve, reject, suspend drivers; restore a deleted driver; audit log; Model tab; Configuration |
| `gate` | Gate | Validate a pass; check in; unloading complete; check out; trucks inside; why a pass is refused |
| `drivers` | Driver chat | Link Telegram; confirm an order; report a delay; Yes or No to a held slot; keep or cancel; change facility; share location |

Each tab also has a task headed `If you see an error` listing that screen's common messages and what to do.
