# GPS-based travel time and delay cross-check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Store truck GPS pings, estimate travel time to the dock, fill a missing repair `travel_minutes` from GPS, and flag driver-reported delays that disagree with GPS by more than 30 minutes.

**Architecture:** A `gps_pings` table and facility coordinates feed a pure travel-time estimator (`travel.py`). A small repository module (`gps.py`) stores and loads pings. `derive_eta` takes an optional `gps_travel_minutes`; with none, behaviour is exactly as today. One signed endpoint (`POST /v1/gps/pings`) is the single way pings enter; the chat-location adapter and the demo console both use the same store function.

**Tech Stack:** Python 3.12, SQLite migrations, FastAPI, Pydantic 2, pytest (+ fakeredis), ruff, mypy. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-21-gps-eta-design.md`

## Global Constraints

- Defaults, all `Settings` fields in `src/setuhaul/config.py`: `gps_max_age_minutes=15`, `gps_mismatch_minutes=30`, `gps_avg_speed_kmph=40.0`, `gps_road_factor=1.3`.
- Mismatch rule: `abs(driver ETA - GPS ETA) > 30 minutes` (exactly 30 is not a discrepancy). GPS ETA is `clock.now() + gps_travel_minutes`.
- Stale rule: a ping older than 15 minutes (`clock.now() - recorded_at > 15 min`) is ignored.
- GPS never overrides the driver's ETA; gate check-in stays highest priority; with no GPS data every existing test passes unchanged.
- `EtaEvidence.source` gains `"GPS_ASSISTED"`; confidence for `GPS_ASSISTED` is capped at `MEDIUM`; a discrepancy lowers confidence one level (HIGH to MEDIUM, MEDIUM to LOW, LOW stays LOW).
- "Now" and ping age always come from the injected `Clock`, never the wall clock.
- Coordinates validated everywhere: lat -90..90, lon -180..180. Timestamps must be timezone-aware.
- The endpoint verifies `x-signature` over the raw body with `verify_channel_request` before parsing, exactly like `/v1/driver/messages`.
- Follow the repo's commenting convention: a short comment on each logical line or block of new code, as in `eta.py`.
- Commit after each task; messages end with the attribution line required for this session.

## Review Focus

- A ping with `recorded_at` in the future (clock skew): treat as age 0, not negative age; test in Task 3.
- Two pings with the same `recorded_at`: the later-inserted one wins; test in Task 3.
- Driver with no unfinished shipment sends a location: rejected with `NO_ACTIVE_SHIPMENT`, nothing stored; test in Task 6.
- Truck already at the dock (distance 0): travel time is 0, not an error; test in Task 2.
- Facility with no coordinates: no GPS estimate, behaviour as today; test in Task 3.
- Repair report that already has `travel_minutes`: driver's figure wins, GPS ignored; test in Task 4.

### Task 4: `derive_eta` uses GPS

**Files:**
- Modify: `src/setuhaul/eta.py` (`derive_eta`)
- Test: `tests/test_eta.py`

**Interfaces:**
- Consumes: `EtaEvidence.gps_discrepancy_minutes`, `source="GPS_ASSISTED"`.
- Produces: `derive_eta(report, planned, current, gate, clock, *, gps_travel_minutes: int | None = None, gps_mismatch_minutes: int = 30) -> EtaResult`. Both new arguments keyword-only with those defaults, so existing callers are unchanged.
- Behaviour: gate check-in branch untouched. `REPAIR` with `travel_minutes is None` and `gps_travel_minutes is not None` returns ETA `start + repair_minutes + gps_travel_minutes`, source `GPS_ASSISTED`, confidence `min(report.confidence, "MEDIUM")`, baseline `REPAIR_COMPLETION`. `REPAIR` with its own `travel_minutes` ignores GPS. For `LATE_BY` and `EXPLICIT_ETA`, when `gps_travel_minutes` is given and `abs(driver_eta - (clock.now() + gps_travel_minutes)) > gps_mismatch_minutes` minutes, return the unchanged driver ETA with confidence lowered one level and `gps_discrepancy_minutes` set to the absolute difference in whole minutes; otherwise unchanged.
